# ChurchFinder Egypt — كنيستك أقرب

تطبيق ويب عربي متجاوب لاكتشاف الكنائس والخدمات المحلية في مصر. المشروع يحتوي على واجهة React مستقلة، وتكامل Backend اختياري يعمل من خلال Supabase Auth + PostgreSQL/PostGIS + REST API بسياسات أمان RLS. تبقى الواجهة في وضع بيانات تجريبية واضح حتى يتم ضبط مشروع Supabase بنجاح.

## ما يتضمنه المشروع

- **واجهة React + TypeScript + Vite** مع دعم RTL وتصميم مستوحى من الصورة المرجعية.
- **13 شاشة** للترحيب، المصادقة، اختيار الموقع، الاستكشاف والخريطة، تفاصيل الكنيسة، الاتجاهات، القائمة والفلاتر، الخريطة والنتائج، المطاعم، المفضلة، الملف الشخصي، والمزيد.
- **`/design-preview`** لوحة مستقلة لمعاينة الشاشات كمكونات HTML/CSS فعلية.
- **تسجيل الحساب وتسجيل الدخول والخروج** عبر Supabase Auth عند ضبط المفاتيح. يدعم رسائل تأكيد البريد عندما تكون مفعلة في إعدادات Supabase.
- **قاعدة بيانات** للكنائس والمطاعم والخدمات والقداسات والملفات الشخصية والمفضلة.
- **لوحة مشرف** على `/admin` لإضافة وتعديل وحذف سجلات الكنائس والمطاعم والخدمات، والتحكم في النشر والتوثيق ومصدر المعلومات.
- **حماية RLS**: السجلات المنشورة فقط تظهر للعامة، وكل مستخدم يستطيع الوصول إلى مفضلته، والكتابة الإدارية تتطلب دور `admin`.
- **PostGIS** لتخزين نقاط الأماكن وفهارس جغرافية واستعلام `nearby_churches` و`nearby_restaurants` لنطاق المسافة.
- خريطة تفاعلية عبر Leaflet وOpenStreetMap، وخدمة توجيه عامة تجريبية OSRM.

## متطلبات التشغيل

- Node.js 20 أو أحدث وnpm.
- اتصال إنترنت عند تنزيل حزم npm، وعند استخدام خرائط OpenStreetMap أو Supabase.
- مشروع Supabase مجاني أو مدفوع خاص بك إذا أردت تشغيل الباك إند الحقيقي. لن تعمل المصادقة أو لوحة الإدارة مع قاعدة بيانات حقيقية قبل هذه الخطوة.

## التشغيل محليًا — وضع العرض

```bash
npm install
npm run dev
```

افتح عنوان Vite الظاهر في الطرفية، وغالبًا `http://localhost:5173`. من ويندوز يمكن تشغيل `START-WINDOWS.bat` بعد تثبيت Node.js. يعمل وضع العرض بدون إعداد Supabase، لكنه يستخدم بيانات داخل المشروع لا تمثل دليلًا حقيقيًا موثقًا.

## إعداد الباك إند الحقيقي

### 1. إنشاء مشروع Supabase

أنشئ مشروعًا في [Supabase](https://supabase.com/)، ثم افتح **Project Settings → API** أو **Connect** للحصول على Project URL والمفتاح العام **Publishable key** الذي يبدأ بـ `sb_publishable_`. المفتاح العام مسموح بوجوده في تطبيق المتصفح لأن RLS تحمي البيانات. **لا تضع Secret أو service_role key في ملفات `VITE_` مطلقًا.**

### 2. إنشاء الجداول وسياسات الأمان

من لوحة Supabase افتح **SQL Editor → New query**، ثم انسخ وشغّل كامل الملف:

`supabase/migrations/202610230001_initial_schema.sql`

ينشئ الملف جداول `profiles`, `churches`, `restaurants`, `church_services`, `favorites`، وسياسات RLS، ومشغلات تحديث الإحداثيات، وفهارس PostGIS واستعلامات الأماكن القريبة. إذا كان مشروعك يحتوي مسبقًا على PostGIS في مخطط مختلف أو جداول تحمل الأسماء نفسها، راجع مخطط قاعدة البيانات قبل تشغيل الـ migration.

### 3. إعداد متغيرات البيئة

في جذر المشروع، انسخ ملف المثال:

**PowerShell:**
```powershell
Copy-Item .env.example .env.local
```

افتح `.env.local` واستبدل القيم التجريبية:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_PUBLIC_KEY
```

أوقف خادم Vite ثم شغّله من جديد بعد تعديل ملف البيئة. لا ترفع `.env.local` إلى Git.

### 4. إعداد المصادقة

من لوحة Supabase افتح **Authentication → URL Configuration** وضبط Site URL وRedirect URLs على عنوان التطوير وعناوين موقعك المنشور. قرر ما إذا كان تأكيد البريد مطلوبًا. عند تفعيله، سيحتاج المستخدم لتأكيد الرسالة ثم تسجيل الدخول. إعداد مزود البريد وحدود الإرسال يخضع لمشروع Supabase نفسه.

### 5. إنشاء حساب المشرف الأول

1. شغّل التطبيق بعد ضبط البيئة.
2. أنشئ حسابًا من `/auth` وتأكد من البريد إذا كانت الخاصية مفعلة.
3. في Supabase SQL Editor نفّذ الاستعلام التالي بعد استبدال البريد ببريد حسابك:

```sql
update public.profiles p
set role = 'admin'
from auth.users u
where p.id = u.id
  and lower(u.email) = lower('YOUR_EMAIL@example.com');
```

4. سجّل الخروج ثم الدخول مرة أخرى، وافتح `/admin` أو ادخل إليها من الملف الشخصي.

هذا التعيين يتم عبر لوحة قاعدة البيانات، لا من متصفح المستخدم. سيمنع الباك إند الحسابات العادية من رفع صلاحيتها بنفسها.

## ملاحظات البيانات والتوثيق

- قاعدة البيانات تبدأ **فارغة** عمدًا؛ لا نزرع أسماء أو مواعيد غير متحقق منها ونقدمها كحقائق.
- حتى بعد اتصال Supabase، لا يظهر للعامة إلا السجل الذي `is_published = true`.
- يوجد حقل توثيق مستقل (`verified`) للسجل، و`is_verified` لمواعيد الخدمات. النشر والتوثيق ليسا الشيء نفسه؛ يجب مراجعة مصدر البيانات قبل الاختيار.
- أضف رابطًا ومسمى للمصدر عندما تتوفر معلومة موثوقة. لا تضف رقم هاتف أو موعد قداس بالتخمين.
- وضع العرض البديل ما زال يستخدم عينات قديمة لاختبار الواجهة، وتظهر معه رسالة تحذير. لا تمثل العينة تغطية كاملة لمحافظات مصر.

## حدود النسخة الحالية / ما يحتاج حسابًا خارجيًا

- لم يتم إنشاء مشروع Supabase خارجي بالنيابة عنك؛ لذلك لم تُنفذ migration داخل قاعدة حية ولم تُنشأ مفاتيح حقيقية أو حساب مشرف جاهز. أكمل الخطوات أعلاه ببيانات مشروعك.
- بيانات الدليل لا تُحمّل تلقائيًا من مصادر مصرية رسمية حتى الآن؛ يلزم إدخالها ومراجعتها أو بناء استيراد من مصدر مرخص وموثوق.
- الصور تعتمد على روابط عامة خارجية عند وجودها، وليست خدمة تخزين صور خاصة.
- الخريطة تستخدم OpenStreetMap وواجهة التوجيه العامة OSRM كتجربة. قبل الإطلاق واسع النطاق، راجع شروط مزودي الخرائط واستبدل خدمة التوجيه العامة بخدمة مستقرة مناسبة لحجم الاستخدام.
- التفضيلات البسيطة مثل وضع اللون وبعض إعدادات الواجهة محلية؛ تفضيلات التنبيهات واللغة تحتاج إعدادات خادم إضافية إن أريدت مزامنتها عبر الأجهزة.
- نفذت فحصًا لصياغة ملفات TypeScript، لكن لم أستطع إتمام `npm install` أو فحص بناء Vite في بيئة الإنشاء الحالية لأن DNS لا يستطيع الوصول إلى `registry.npmjs.org`. نفّذ `npm install` ثم `npm run build` على جهاز متصل بالإنترنت للتحقق النهائي.
